# 域名与部署

GitHub 仓库：<https://github.com/nemochenyx/nemochenyx.github.io>

默认网站：<https://nemochenyx.github.io/>

用户选择的正式域名：`yuxingnemochen.com`。

## 发布方式

GitHub Pages 的 Source 使用 **GitHub Actions**。工作流位于 `.github/workflows/deploy.yml`，每次向 `main` 提交后生成网站、检查内部链接、发布 Pages。无需上传 `public/`。

Hugo 的固定版本为 0.147.0 extended，本地预览与线上构建使用同一版本。

## 域名记录

依据 [GitHub 官方文档](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)，先在仓库 Settings → Pages 设置 Custom domain，再在 Cloudflare 配置以下记录：

| 类型 | Name | Target |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `nemochenyx.github.io` |

当前 TTL 为 300 秒（5 分钟）。DNS 配置阶段使用 DNS only，让 GitHub 直接验证并签发证书。保留任何已有的邮件相关 MX、TXT 等记录。

GitHub Pages 验证域名后，启用 **Enforce HTTPS**。Hugo 的 `baseURL` 改为 `https://yuxingnemochen.com/`，使规范地址及 sitemap 与正式域名一致。GitHub Actions 发布模式下，域名以 Pages 设置为准，`CNAME` 文件不是必须的。

DNS 和证书可能需要等待生效；不能只凭设置已保存就认定网站已上线。最终需要检查首页、四个页面、PDF、域名解析和 HTTPS。

## 检查与排错

本地构建：`.local/tools/hugo --gc --minify`。

链接检查：`python3 scripts/check-site.py`。

如果提交后网页未更新，打开 GitHub 仓库的 Actions，检查最近一次运行。绿色代表完成，红色需要查看失败步骤。域名问题先检查 Cloudflare 的 DNS 记录，再检查 GitHub Pages 的域名验证与证书状态。
